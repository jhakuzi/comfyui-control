# ComfyUI Control 1.0.0

The first stable 1.0 release brings the tested desktop, mobile and SSH features
together. Existing configuration, workflow mappings and mobile sessions carry over.

- Responsive WebUI for phones, iPads and laptops, with live progress, previews,
  s/it, VRAM and GPU usage. Wider screens put progress in a pinned top header.
- Reuse prompts/settings from Mobile WebUI jobs or workflows embedded in local
  ComfyUI PNGs. Custom nodes, GGUF loaders, LoRAs and mapped controls are preserved.
- Optional sharing of image prompts/settings between trusted browsers, so laptop
  generations can be reused from a phone. Live jobs, cancellation and prompt
  history remain separate. Enable sharing in desktop **Mobile WebUI**, then Apply.
- Sharper gallery thumbnails on larger/high-density screens, image comparison,
  metadata inspection, downloads and reconnect recovery.
- Foreground SSH startup: `comfyui-control --start-server --start-webui`.
  No desktop login is needed; Ctrl+C stops the owned ComfyUI processes and WebUI.
- Tray controls with a remembered close preference, plus optional NFS output,
  local fallback warnings and a gallery that follows the active destination.
  `/etc/fstab` is untouched; other mounts and NAS image files are left alone.

## Install or update

Fedora 44 x86_64:

```bash
sudo dnf copr enable jhakuzi/comfyui-control
sudo dnf install comfyui-control
```

For an existing installation:

```bash
sudo dnf upgrade --refresh comfyui-control
```

RPM `1.0.0-1` upgrades the RC1/RC2 versions normally. Close a testing copy before
opening the installed app; both use your existing configuration and instance lock.

For Fedora, Debian/Ubuntu or Arch without RPMs, download `comfyui-control.zip`,
extract it and run `bash install.sh` as your normal user. Screenshots and tests
are excluded from that download. ComfyUI, GPU drivers and models are separate.

## Verification and practical limits

The release was checked with automated application tests, Chromium/Linux WebKit
protocol tests and Fedora RPM packaging. The user separately confirmed real
phone/laptop/iPad use, SSH startup, NFS/fallback, tray/settings persistence,
generation controls, iPhone reconnect recovery and cross-device reuse.

Automated generation tests use protocol fixtures rather than GPU inference.
Custom workflows still need valid installed nodes/models and saved input mappings;
PNG reuse needs embedded API workflow metadata. Mobile WebUI and cross-browser
image sharing are off by default. Enable sharing only for trusted browsers that
can access the WebUI. HTTP LAN/VPN sites work normally; full PWA features require
a browser-supported secure context such as trusted HTTPS.
