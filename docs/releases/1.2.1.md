# ComfyUI Control 1.2.1

Fix Preview & results showing an older image even after reloading when ComfyUI
reuses a filename belonging to a previously deleted generation.

The Gallery knew the new file timestamp, while an unversioned completed-job
reference could still match an old deletion marker and be hidden from Preview.
Completed outputs now resolve their actual file version before deletion filtering,
without requiring a Gallery visit. File checks run in a bounded isolated worker.

- New outputs use their current file timestamp and remain visible after reload.
- Older deleted generations and unchanged deleted files stay hidden. Missing,
  symlinked or inaccessible storage never clears a deletion marker.
- Reused filenames cannot inherit the previous generation's timestamp or thumbnail
  cache identity. Unversioned images use a generation-specific URL/cache key.
- Completion references are journaled before storage checks, so cancellation or
  shutdown while resolving metadata cannot discard the saved result.

Verified with local/network output fixtures and browser pixel checks; also checked
against a temporary identity-only copy of the affected user's saved record with
read-only file metadata access. Original images/configuration were not modified.

## Update

```bash
sudo dnf upgrade --refresh comfyui-control
```

Restart the desktop app, then reload Desktop/Phone WebUI pages with Ctrl+Shift+R.
For ZIP installation, extract the updated app ZIP and run `bash install.sh` as your
normal user. Existing deletion markers and library settings are preserved.
